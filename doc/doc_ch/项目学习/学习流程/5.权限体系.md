# 权限体系(Casbin RBAC)

> 代码位置：`code/backend/server_py/src/module_authorization`
> 核心文件：`config/casbin_rule.py`(策略声明) / `dependencies/permission.py`(校验依赖)

## 1. 模型与域划分

项目采用 **Domain-Separated RBAC** 模型(`rbac_model.conf`)：

```
g = _, _          # 角色绑定(user, role, dom)
p = sub, dom, obj, act   # 策略(角色, 域, 资源, 动作)
```

域(dom)划分约定：

| 域 | 含义 |
| :--- | :--- |
| `*` | 全局域，系统管理员，穿透所有子模块 |
| `main` | 主模块域(字典/状态/数据库/文件等基础资源) |
| `rag` | 知识库模块全局域(项目列表等模块级资源) |
| `rag:{project_id}` | 具体知识库项目域，实现**同知识库多用户隔离** |

## 2. 动作(act)约定

| 动作 | 含义 |
| :---: | :--- |
| `read` | 查看 / 下载 |
| `create` | 新建 / 上传 |
| `update` | 修改 / 重命名 / 移动 |
| `delete` | 删除 |
| `manage` | 管理类操作(成员管理等) |

## 3. 内置角色预设

各子模块默认策略在 `casbin_rule.py` 的 `MODULE_POLICY_PRESETS` 中**声明式定义**，应用启动时幂等写入数据库：

```python
# 主模块: 基础资源(字典/状态/数据库/文件)
MAIN_POLICY_PRESET = ModulePolicyPreset(
    module="main",
    rules=[
        # 主模块管理员: 全部基础资源读写
        ("main_admin", "main", "*", "read|create|update|delete"),
        # 主模块运维: 可读写不可删
        ("main_operator", "main", "*", "read|create|update"),
        # 主模块访客: 只读
        ("main_viewer", "main", "*", "read"),
        # ---- 文件子模块(虚拟文件系统)独立策略 ----
        ("main_admin", "main", "file", "read|create|update|delete"),
        ("main_operator", "main", "file", "read|create|update"),
        ("main_viewer", "main", "file", "read"),
    ],
)
```

> 同一域下**窄资源规则优先于 `*` 通配规则**，因此可对子模块单独收紧/放开权限。

## 4. 后端接入方式

### 路由级校验(推荐)

```python
from module_authorization.dependencies.permission import require_permission

@router.get("/list_dir")
async def list_dir(
    current_user_id: str = Depends(
        require_permission("main", "file", "read")
    ),
    service: FileService = Depends(get_file_service),
):
    ...
```

`require_permission(module, obj, act)` 返回 FastAPI 依赖：

1. 先解析当前登录用户(内部依赖 `get_current_user_id`，校验 Token)
2. 再以 `(user, dom, obj, act)` 调 casbin `enforce`
3. 无权限自动抛 **403**

### 项目级校验(知识库多用户隔离)

路由路径含 `{project_id}` 时使用 `require_project_permission`，
域自动构造为 `rag:{project_id}`：

```python
@router.post("/{project_id}/upload")
async def upload(
    project_id: str,
    user_id: str = Depends(require_project_permission("doc", "upload")),
):
    ...
```

### 服务层手动校验

已知 project_id 的场景可在 Service 内直接调用：

```python
from module_authorization.dependencies.permission import enforce_project_permission

await enforce_project_permission(user_id, project_id, "doc", "delete")
```

## 5. 新模块接入权限的步骤

1. 在 `casbin_rule.py` 对应预设(`MAIN_POLICY_PRESET` / `RAG_POLICY_PRESET`)中声明
   `(角色, 域, 资源, 动作)` 规则
2. Controller 路由挂上 `require_permission(...)` 依赖
3. 重启后端，规则幂等写入即生效
4. 前端无需感知：403 由 axios 拦截器统一提示

## 6. 角色绑定管理

- 用户-角色绑定存储于 casbin 规则表，由 `module_authorization` 的
  角色管理接口维护(前端页面：`/_sys/manager/role`、`/_sys/manager/casbin`)
- 知识库项目成员角色变更时，后端通过 `sync_project_member_role`
  同步 `rag:{project_id}` 域的分组策略
- 用户被移出项目时调用 `remove_project_*` 清理对应域授权

## 7. 常见问题

| 现象 | 排查 |
| :--- | :--- |
| 接口 403 | 用户未绑定角色；或预设中未声明该 `dom/obj/act` |
| 改了策略不生效 | 重启后端(预设仅启动时写入)；或数据库中已有同名旧策略 |
| Token 失效 401 | 登录态过期，前端会引导重新登录 |
| 管理员也被拦截 | 全局管理员需绑定 `*` 域角色 |
