## 2. 现状已满足的新版要求（无需改动）

1. **两级权限体系**：系统级 Casbin 域隔离 RBAC + 项目级成员档位，项目级不走 Casbin 项目域（`module_rag/dependencies/permission.py`）。
2. **默认私有**：`Project/ProjectCreate/ProjectResponse` 的 `is_private` 均默认 `True`。
3. **创建即拥有**：`module_rag/controller/project.py` `create_project` → `service/project.py:105-135` 填充 `created_by` 并写 `role=PROJECT_ADMIN` 成员记录。
4. **三档协作与级联**：`project_reader(1)/project_editor(2)/project_admin(3)`，生效档位 = max(直连, 部门授权)，部门链由 `ancestors` 展开。
5. **公开库登录用户只读**：`check_project_permission` 中 `act == "read"` 且 `not project.is_private` 放行。
6. **模型三类隔离与防越权绑定**：`mask_secrets` 对"非本人创建"清空 `url/api_key`；`_validate_model_access` 防止绑定他人模型。
7. **模型兜底链主体**：`resolve_model_id` = 用户绑定（chat/embedding/rerank）→ 使用前归属校验 → 回退 `scope=public 且 is_default=True 且 is_active=True` 的默认公共模型；`get_missing_model_types` 做任务派发前预检。
8. **未登录 401**：全路由认证依赖覆盖。

## 3. 差距与实现方案

### 3.1 [P0] 项目列表可见性过滤（私有库列表隐身）

**现状**：`module_rag/dao/project.py` 的 `list_paged/count` 只有 `name/kb_category/is_private` 过滤；`controller/project.py` 的 `/list` 只要求 `rag:project:read`（普通用户默认策略含此权限码）。

**方案**：DAO 增加按"查看者"的可见性条件（对齐 v4 5.1 的 EXISTS 写法），controller 传入当前用户；admin 跳过过滤：

```python
# module_rag/dao/project.py — list_paged/count 增加 viewer_id 参数
from sqlmodel import or_, exists, select, false

def _visibility_condition(self, viewer_id: str, dept_chain: list[str]):
    """私有库仅 创建者/直连成员/部门授权 可见, 公开库所有登录用户可见(v4 5.1)"""
    member_exists = exists(
        select(1).where(
            ProjectMember.project_id == Project.id,
            ProjectMember.user_id == viewer_id,
        )
    )
    # 用户无部门时不得生成 in_([]) 非法 SQL(v4 5.1 注 2)
    dept_exists = (
        exists(select(1).where(
            ProjectDept.project_id == Project.id,
            ProjectDept.dept_id.in_(dept_chain),
        ))
        if dept_chain else false()
    )
    return or_(
        Project.is_private == False,      # noqa: E712 公开库
        Project.created_by == viewer_id,  # 自己创建的
        member_exists,
        dept_exists,
    )
```

```python
# module_rag/controller/project.py — /list 改为认证依赖 + admin 跳过
@router.get("/list", summary="分页查询项目列表(私有库仅授权人可见)", ...)
async def list_projects(
    ...,
    current_user_id: str = Depends(get_current_user_id),
    _perm=Depends(require_permission("rag", "project", "read")),
):
    # admin 跳过可见性过滤(系统审计, v4 5.1 注 1)
    viewer_id = None if await is_global_admin(current_user_id) else current_user_id
    return await service.list_paged(..., viewer_id=viewer_id)
```

实现要点：

- 部门链 `get_user_dept_chain(user_id)` 每请求只查一次，list/count 复用（v4 5.1 注 3）；
- 提取公共函数 `is_global_admin(user_id)`（封装 `enforcer.has_grouping_policy(user_id, "admin", "*")`，当前在 `module_rag/dependencies/permission.py:85` 与 `module_rag/service/user_model.py:59` 重复两处）；
- 已有的成员视角接口 `ProjectMemberService.list_my_projects` 保留，二者互补：`/list` = 可见列表，`/my` = 成员列表。

### 3.2 [P0] 公开/私有切换需 project_admin 档位（publish 动作）

**现状**：`update_project` 走 `("project","update")` → 档位 2，editor 可将私有库切为公开（数据泄露入口）。

**方案**：新增档位 3 动作 `publish`（v4 2.2/3.1），service 层对 `is_private` 变更单独校验：

```python
# module_rag/dependencies/permission.py
ACTION_LEVELS: dict[str, int] = {
    ...,
    "publish": 3,  # 设置公开/私有: 仅 project_admin(v4 3.1)
}

# module_rag/service/project.py — update() 内
existing = await self.get(project_id)
if existing and project.is_private is not None and project.is_private != existing.is_private:
    await enforce_project_permission(current_user_id, project_id, "project", "publish")
```

注意：`enforce_project_permission` 需要 `current_user_id`，controller 需把它传进 service（当前 `update` 未传）。

### 3.3 [P1] 私有库详情读访问 404 化（防存在性探测）

**现状**：`enforce_project_permission` 对无权限统一抛 403。

**方案**（v4 3.3 补充/5.2 第 5 步已定案）：仅 `read` 动作 + 私有库 + 非成员（档位 0）时改抛 `NotFoundError`（404）；已登录成员档位不足仍 403，写动作仍 403。改造集中在 `module_rag/dependencies/permission.py` 的 `check/enforce` 两函数。顺带按项目异常体系规约把 403 从裸 `HTTPException` 改为 `ForbiddenError`（`common.utils.fastapiEX.exceptions`），保持既有测试语义一致。

### 3.4 [P1] 列表返回 `my_perms` 权限位

**方案**（字段与映射对齐 v4 5.3）：

```python
class ProjectMyPerms(SQLModel):
    """当前用户对单个知识库的操作权限位(前端按位渲染按钮)"""
    read: bool = False            # 档位>=1
    upload_doc: bool = False      # 映射动作 upload, 档位>=2
    update: bool = False          # 档位>=2
    delete: bool = False          # 档位>=3
    manage_member: bool = False   # 映射动作 invite/remove/manage, 档位>=3
```

计算方式：分页场景禁止逐项目调 `check_project_permission`（N+1）。一次性取当页 `project_ids` → 批量查 `project_member(user_id, project_id in ids)` 与 `project_dept(dept_id in dept_chain, project_id in ids)` → 内存取 max 档位 → 映射动作位；admin 全 True。详情接口复用同一函数。

### 3.5 [P1] 至少保留一个激活的 project_admin 保底

**现状**：成员移除/降级、部门授权增删改均无 admin 数量校验。

**方案**（v4 3.2 规则 3）：成员与部门授权两条线的写操作前统一校验：

```python
async def _assert_admin_remaining(
    self, project_id: str,
    exclude_member_id: str | None = None,   # update 降级场景排除自身旧档位
) -> None:
    """移除/降级后必须仍有激活的 project_admin(直连成员或部门授权来源均计入, v4 3.2)"""
    direct = await self.member_dao.count_admins(
        project_id, exclude_member_id=exclude_member_id, active_only=True  # join user 表过滤 is_active
    )
    via_dept = await self.dept_dao.count_admins(project_id)
    if direct + via_dept == 0:
        raise ConflictError("必须至少保留一个项目管理员(project_admin)")
```

覆盖点：`member.delete`（目标是 admin 时）、`member.update`（降级 admin 时）、`project_dept` 移除/降级 admin 授权时。边界处理见 §4.3。

### 3.6 [P1] 兜底链可感知 + 用户级回退开关

**现状**：`resolve_model_id` 在绑定失效时静默回退默认公共模型，用户无感知（v4 4.3 认定为隐私问题：数据流向改变）。

**方案**：

```python
# module_rag/service/user_model.py — 解析结果带回退标记
from typing import NamedTuple

class ResolvedModel(NamedTuple):
    model_id: str | None
    fallback_used: bool = False  # True=绑定失效/未绑定, 已回退默认公共模型

async def resolve_model(self, user_id: str, model_type: ModelType) -> ResolvedModel:
    """绑定 → 归属校验 → (开关允许时)回退默认公共模型; 结果标记是否发生回退"""
    binding_id = await self._get_binding_id(user_id, model_type)
    if binding_id:
        try:
            await self._validate_model_access(binding_id, user_id)
            return ResolvedModel(model_id=binding_id)
        except (ValueError, NotFoundError):
            pass  # 绑定失效, 走回退
    if await self._fallback_disabled(user_id):  # 用户级开关: 不回退直接报错
        return ResolvedModel(model_id=None)
    fallback_id = await self._get_fallback_model_id(model_type)
    return ResolvedModel(model_id=fallback_id, fallback_used=fallback_id is not None)
```

- **开关存储**：`user_model` 表加 `fallback_disabled: bool = Field(default=False)`，按项目惯例用启动钩子补列（参照 `module_ai/config/server.py` 的 `ensure_model_config_scope_columns` 模式）；
- **可感知**：调用方（chat 流式/非流式、向量化）依据 `fallback_used` 在 SSE 首包 meta 或响应 meta 提示"绑定的模型不可用，已回退系统公共模型"；开关关闭且无可用模型时抛 `BusinessError`（400）而非静默换模型。

### 3.7 [P2] 模型 admin 边界（v4 已定案，按三处差异落地）

v4 4.1/4.2 定案为"元数据全量可见、密钥除本人外脱敏、不可用他人私有"，与现状三处差异：

| 落点 | 现状 | 改为 |
|------|------|------|
| `module_ai/dao/model_config.py` `_visibility_condition` | admin 返回 None（全量可见） | **保持不变**（恰好符合 v4"查看列表=全量元数据"） |
| `module_ai/service/model_config.py` `mask_secrets` | `if configs is None or is_admin: return`（admin 全明文） | 删除 `or is_admin` 豁免：仅 `scope=user 且 user_id==本人` 保留明文，公共/部门/他人私有一律脱敏（含 admin） |
| `module_rag/service/user_model.py` `_validate_model_access` | admin 放行（可绑定使用他人私有） | 删除 admin 放行两行（与 v4 4.2"绑定使用他人私有模型=否"一致） |

补充（v4 4.2 安全要求）：私有模型 create/update 校验 `base_url`（协议白名单 http/https + 可选域名黑名单，黑名单走配置），写操作记审计日志（logging 起步即可）。

## 4. 实施注意事项

1. **`my_perms` 命名映射**：对外字段按 v4 5.3（`upload_doc`/`manage_member`），内部映射到 `ACTION_LEVELS` 的 `upload`/`invite`/`remove`/`manage`，映射关系写入接口文档，避免前后端各叫一套。
2. **SQL 细节**：可见性用 `EXISTS` 而非 `IN (SELECT ...)`；用户无部门时用 `false()` 占位，禁止 `in_([])`；部门链一次查询复用。
3. **保底边界**：`count_admins` 需 join `user` 表过滤 `is_active=true`（唯一 admin 被禁用也拦截）；部门授权来源计入统计；admin 的 Casbin 穿透保证系统层面兜底，业务保底仅防"业务层孤儿"（v4 3.2 已写明，不要过度设计）。
4. **`is_global_admin` 提取**：公共函数放 `module_authorization` 侧（或 `common`），`module_rag` 两处引用改为复用。
5. **异常体系统一**：项目级 403/404 改用 `ForbiddenError`/`NotFoundError`，controller 不再出现裸 `HTTPException` 透传；改动后核对现有 tests 的断言（403/404 状态码不变，仅异常载体变化）。
6. **前端配套**：项目列表按 `my_perms` 渲染操作按钮（无权限入口直接隐藏）；项目设置页"公开/私有"开关仅对具备 `manage_member`（或 `delete`）位的用户可编辑；模型页私有模型文案与"回退提示"展示；用户设置页新增"模型回退开关"。

## 6. 测试要求（按项目规约）

后端标准测试落在 `code/backend/server_py/tests`，零外部依赖，鉴权 fixture 携带 token。重点用例：

- **列表隐身**：普通用户 `/list` 不含他人私有库；分别构造 创建者命中 / 直连成员命中 / 部门授权命中（含祖级级联） / 公开库全员可见 各一例；admin 列表返回全量；无部门用户不产生非法 SQL。
- **publish 档位**：editor 改 `is_private` 被拒（403）；project_admin 改成功（204）。
- **404/403 语义**：非成员 GET 私有库 404；成员档位不足 403；公开库非成员 GET 200。
- **保底**：移除/降级最后一个激活 admin 被拒（409）；部门授权来源可满足保底；唯一 admin 被禁用后再移除其他成员触发拦截。
- **my_perms**：各档位成员的权限位与矩阵一致；admin 全 True。
- **模型边界**：非本人（含 admin）查看模型 url/api_key 已脱敏；本人私有模型明文可见；admin 绑定他人私有模型被拒（走回退路径）；`base_url` 非法协议返回 400。
- **兜底链**：绑定失效回退时 `fallback_used=true` 且响应含提示；开关关闭时绑定失效返回 400 不回退；无默认公共模型时返回"无可用模型"。
