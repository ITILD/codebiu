## 1. 总体架构

```
┌──────────────────────────── 浏览器 ────────────────────────────┐
│  Vue3 SPA（pages + modules/* 页面，unplugin-vue-router 自动路由） │
│  Element Plus + UnoCSS + Pinia + fetch-event-source(SSE)       │
└──────────────┬─────────────────────────────────────────────────┘
               │ /base_server/**（Vite dev 代理 → 后端 2001）
┌──────────────▼─────────────────────────────────────────────────┐
│              FastAPI 主应用（BizFastAPI, 端口 2001）             │
│  中间件: CORS / GZIP / X-Process-Time 耗时统计                   │
│  ├─ module_main        字典/状态/DB工具/静态托管（直接挂主应用）    │
│  ├─ /authorization     认证授权（JWT + Casbin RBAC）             │
│  ├─ /file              统一文件存储（虚拟文件树 + S3/local）       │
│  ├─ /websearch         多引擎网页搜索                            │
│  ├─ /rag               知识库（项目/文档/分块/成员/问答）          │
│  ├─ /agent             智能体（LangGraph 单节点图）               │
│  ├─ /ai                模型配置/LLM 对话/语音/OCR                 │
│  ├─ /site /task /data-clean /geometry /nlp /life /dev-tools     │
│  └─ /template /office /contact(工具) /graph(工具)                │
└───────┬───────────────┬───────────────┬───────────────┬────────┘
        │               │               │               │
   PostgreSQL      Redis/Fakeredis   Milvus/LanceDB    Neo4j
   (业务表/Casbin/   (黑名单/Celery     (向量+BM25       (图谱预留)
    checkpointer)    broker/backend)    混合检索)
        │
        ▼ Celery worker（src/app_task.py, 队列 task_queue）
   文档解析/向量化等异步任务 ←— S3/本地存储（统一文件服务）
```

**设计基调**

- **模块自治**：每个 `module_*` 内部分层为 `controller / service / dao / do / config / dependencies`，经 `app.py` 导入 controller 完成路由挂载，经导入 `config/permissions.py` 完成权限注册。
- **子应用隔离**：业务模块以子应用（`BizFastAPI` 实例）形式挂载，保证全局异常处理行为一致（BizError → 自带状态码 / ValueError → 400 / 兜底 → 500 + 日志）。
- **可切换存储**：`DatabaseManager`（`common/config/db.py`）统一管理四类数据库连接与建表生命周期；`db_factory` 按配置创建具体实现。

## 5. 核心功能流程设计

### 5.1 认证与令牌

```
登录/注册 ──► 校验密码(argon2) + is_active
         ──► 签发 access_token（仅客户端） + refresh_token（落库 token 表）
         ──► 返回 { tokens: {access, refresh}, user }
请求时 ──► Authorization: Bearer <access>
       ──► JWT 签名校验 + Redis 黑名单检查（缓存故障降级放行）
       ──► require_permission(dom, obj, act) / require_project_permission(...)
刷新 ──► POST /authorization/auth/refresh
       ──► refresh 校验（签名 + 库内 is_revoked）→ 换发新 access
登出 ──► access 写入 Redis 黑名单 + refresh 置 is_revoked
```

### 5.2 知识库文档入库（RAG Ingest）

```
上传文件 ──► module_file 统一文件服务
            （SHA-256 去重秒传 / S3 预签名直传 / 分片断点续传）
        ──► project_document 记录创建（parse_status 跟踪）
        ──► 投递 Celery 任务（module_task: task_queue 表 + celery_task_id）
worker ──► 解析：module_office ParserFactory（pdf/docx/pptx/xlsx/md → docling；
            .py/.java → 代码语义切分；可由 LLM 推荐切分策略 general/tables）
       ──► 切分：ChunkConfig → ChunkedItem 列表
       ──► 向量化：用户绑定的 Embedding 模型 → 稠密向量 + BM25 稀疏自动生成
       ──► 写入向量集合 projectdocumentchunk（按 project_id 隔离）
       ──► 进度双写：task_queue.progress + Celery update_state(PROGRESS)
```

### 5.3 知识库问答（RAG Chat，LangGraph）

```
POST /rag/rag-chat/{conversation_id}/chat   (SSE)
  │
  ├─ 无关联知识库 ──────────────► chat 节点（普通 LLM 对话）
  └─ 有关联知识库
       ├─ intent_analysis 节点：结构化输出 RagHelpInfo
       │    （提取检索关键词 / 判断是否需要外部知识）
       ├─ knowledge_search 节点：
       │    稠密检索(COSINE) + 稀疏检索(BM25) ──RRF 融合──► 可选 Rerank 精排
       │    （深度思考开关；score_threshold 过滤）
       └─ chat 节点：RAG 系统提示词模板 + 检索片段 + 历史消息(AsyncPostgresSaver
            checkpointer, thread_id=conversation_id) → 流式生成
```

**SSE 事件协议**（全项目统一，`module_ai/utils/llm/response/sse.py::event_generator`）：

```jsonc
// 每条 event.data 均为 JSON：
{ "status": "start" | "stream" | "end" | "error",
  "content": "...", "response_id": "...", "node_name": "intent_analysis|knowledge_search|chat",
  "stream_event_type": "llm_thinking|agent_thinking|agent_thinking_conclusion|tool_call|file_gen|answer|status|error" }
```

- 服务端检测 `request.is_disconnected()` 主动断流；异常时 yield `error` 事件。
- 会话收尾异步压缩历史并自动生成会话标题（summary graph）。

### 5.4 智能体对话（module_agent）

- 编排：**单节点 StateGraph（chat 节点）** 服务所有智能体；对话关联 agent 的 `system_prompt` 动态注入，未关联或已删除用默认提示词兜底。
- 状态：`AgentChatState`（MessagesState + system_prompt + user_id）；checkpointer 复用 RAG 的 AsyncPostgresSaver；对话/消息复用 `conversation`/`chat_message` 表（agent_id 区分）。
- 模型：按用户绑定 chat 模型加载（`UserModelService.get_llm_by_user_id`）。
- 启动时 `seed_builtin_agents` 幂等写入内置智能体（固定 ID，不可删除）。

### 5.5 统一文件服务（module_file）

```
smallDirect（小文件）: FormData 直传 → 内容哈希查重（命中则秒传建条目）
direct（大文件, S3）: init 签发预签名 URL → 浏览器逐片 PUT 直传(读 ETag) → complete 对账
proxy（大文件, 中转）: 小于 max_size 直接中转；否则逐片经服务端转发
存储抽象: FileContent（content_hash 主键, ref_count 引用计数）
          + FileEntry（虚拟目录树, 逻辑删除, 引用归零清理物理文件）
下载: S3 → 302 直链；local → 流式响应
```

### 5.6 异步任务（module_task）

- 消息只传 `task_queue` 主键，worker 读取 payload 执行；`task_queue` 表为状态事实来源（pending/running/success/failed/cancelled/revoked）。
- API：创建投递、注册表查询、状态统计、详情、Celery 状态对账（sync）、取消、重试、删除。
- 业务注册任务：`run_demo_document`、`reparse_document_task`、`revectorize_chunks_task`。

### 6.2 自动路由与布局分流（vite.config.ts `extendRoute`）

| 路由来源 | meta | 行为 |
|----------|------|------|
| `src/pages/index.vue`、`[..all].vue` | 无 | 公开页 |

> 注意：`agent` 模块在菜单配置中标记为 mainApp，但 extendRoute 正则仅覆盖 site/rag/geometry，其路由 meta 实为 `admin`（渲染侧边栏），属已知实现现状。

### 6.3 HTTP 封装（`src/common/api/http.ts`）

- 原生 fetch 封装的 `HttpClient` 单例：`apiPrefix=/base_server`、超时 300s（AbortController，适配 LLM 长请求）；
- 请求拦截：自动附加 `Authorization: Bearer`；非 FormData 默认 JSON 头；
- **401 单飞刷新**：共享同一次 refresh 请求，成功后重试原请求一次；刷新失败 `forceReLogin()` 跳首页并带 `?login=1` 打开登录弹窗；
- 响应：`!ok` 抛错（优先 `detail` 字段）；204 → null；其余返回 JSON。

| Store | 持久化 | 职责 |

| `auth` | ✅ | tokens（access/refresh）、user、roles/permissions；`fetchPermissions()` 拉取权限码 |
| `Router` | ❌ | 当前路径，侧边栏高亮 |
| `sysSetting` | 主题经 useDark 持久化 | 头部/侧边栏/抽屉显隐、主题三态、语言、断点 |

### 6.5 流式对话组件链

```
页面(ai/chat.vue | rag/conversation.vue | agent/chat.vue)
  = 会话列表 + ChatMessageList + ChatComposer
fetch-event-source(POST, Bearer) ──► onChunk/onEvent(JSON 解析 ChatStreamEvent)
  ├─ ProcessBlock：按 stream_event_type 分组折叠过程区块
  └─ MarkdownContent：LaTeX 保护 → marked 分词 → Mermaid/Table 分流渲染
智能滚动：接近底部才跟随；等待首 token 显示思考动画；AbortController 停止生成
```

- AI 通用聊天历史存 localStorage（`ai_chat_history` 等）；RAG/Agent 会话走后端持久化。
- 语音：ASR 文件（POST FormData）/ ASR 流式（WebSocket，token 走查询参数）/ TTS 文件（Blob）/ TTS 流式（ReadableStream 逐块 PCM，采样率取响应头）。

### 6.6 样式与工程约定

- 主题：`--note-*` CSS 变量（淡绿自然笔记风）+ UnoCSS shortcut（`page-card`/`h-app` 等），主题色一律引用变量，免写 `dark:` 变体；
