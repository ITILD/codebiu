# 03 - 权限设计

> 适用范围：`code/backend/server_py`（FastAPI 后端）与 `code/frontend/vue3`（Vue3 前端）。
> 本文描述系统的权限模型、数据结构、鉴权流程与各模块权限声明，供开发与运维参考。

---

## 1. 设计目标

- **模块自治**：每个业务模块在自己的 `config/permissions.py` 中声明本模块的权限树，模块授权中心统一收集，避免集中式维护导致的冲突。
- **两级权限体系**：
  - **系统级权限**：基于 Casbin 的域隔离 RBAC，控制"模块级"资源（菜单、管理功能）。
  - **项目级权限**：不走 Casbin，由业务模块的成员表固定档位控制（GitHub 式协作），支持部门授权级联。
- **最小默认权限**：新注册用户仅获得各模块显式声明的 `default_policies`，其余权限由管理员按需分配。
- **幂等可重入**：所有声明同步逻辑重复启动安全，零冗余写入。

## 2. 总体权限模型

```
┌──────────────────────────────────────────────────────────┐
│                        请求进入                            │
│        Authorization: Bearer <access_token>               │
└──────────────────────┬───────────────────────────────────┘
                       │
              ┌────────▼─────────┐
              │ JWT 身份认证      │  get_current_user_id
              │ (签名+黑名单校验)  │  (dependencies/auth.py)
              └────────┬─────────┘
                       │
        ┌──────────────▼──────────────┐
        │        两级权限校验           │
        ├─────────────────────────────┤
        │ ① 系统级: Casbin 域隔离 RBAC │  require_permission(module, obj, act)
        │    域=模块名, 控制 API/菜单   │  (dependencies/permission.py)
        ├─────────────────────────────┤
        │ ② 项目级: 成员表档位校验      │  require_project_permission(obj, act)
        │    reader/editor/admin       │  (module_rag/dependencies/permission.py)
        └─────────────────────────────┘
```

| 层级 | 存储位置 | 控制对象 | 典型示例 |
|------|----------|----------|----------|
| 系统级（Casbin RBAC） | `casbin_rule` 表 | 模块菜单、管理类 API | `rag/project/create`（能否创建知识库项目） |
| 项目级（成员档位） | `project_member` / `project_dept` 表 | 项目内资源 | 某项目内能否上传文档、删除成员 |

## 3. 系统级权限：Casbin 域隔离 RBAC

### 3.1 Casbin 模型（rbac_model.conf）

采用 Casbin 官方 `RBAC with Domains` 模型，四元组为 `[主体, 域, 资源, 动作]`：

```ini
[request_definition]
r = sub, dom, obj, act

[policy_definition]
p = sub, dom, obj, act

[role_definition]
g = _, _, _        # g = 用户/角色, 角色, 域 —— 同一用户在不同域可拥有不同角色

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = (g(r.sub, p.sub, r.dom) || g(r.sub, p.sub, "*"))
    && (r.dom == p.dom || p.dom == "*" || keyMatch(r.dom, p.dom + "/*"))
    && (r.obj == p.obj || p.obj == "*")
    && (r.act == p.act || p.act == "*")
```

要点：

- **角色绑定带域**：`g = 用户, 角色, 域`，用户-角色绑定统一存放在全局域 `"*"`。
- **域匹配三种方式**：精确匹配；`p.dom == "*"` 全局策略；`keyMatch(r.dom, p.dom + "/*")` 父域策略作用于子域（如 `rag` 域策略可作用于 `rag:{project_id}` 子域，为未来项目域扩展预留）。
- **管理员穿透**：`admin` 角色持有策略 `("admin", "*", "*", "*")`，匹配任何域/资源/动作。

### 3.2 域（dom）划分约定

| 域 | 含义 | 说明 |
|----|------|------|
| `*` | 全局域 | 内置角色绑定与管理员穿透策略所在 |
| `sys` | 授权模块域 | 用户/角色/部门/权限/策略规则管理 |
| `main` | 基础资源域 | 字典/数据库/虚拟文件系统/网页搜索 |
| `rag` | 知识库域 | 项目/文档/成员/问答等模块级资源 |
| `agent` | 智能体域 | 对话与智能体管理 |
| `site` | 个人小站域 | 博客/备忘/记账 |
| `geometry` | 地理空间域 | 地球绘制与要素存储 |
| `task` | 任务队列域 | Celery 异步任务管理 |

### 3.3 角色体系

**内置角色仅两个**（`module_authorization/config/casbin_rule.py` 中 `BUILTIN_ROLES`）：

| role_key | 名称 | 说明 |
|----------|------|------|
| `admin` | 系统管理员 | 策略 `("admin","*","*","*")`，穿透一切；首个注册用户自动获得 |
| `user` | 普通用户 | 策略由各模块 `default_policies` 声明合并而来 |

其余角色由管理员在"角色管理"界面自建，并勾选权限树的按钮级权限码。

### 3.4 权限码（code）约定

采用三段式权限码，与 Casbin 四元组的后三项一一对应：

| 形式 | 节点类型（menu_type） | 示例 | 说明 |
|------|----------------------|------|------|
| `模块` | M（目录） | `rag` | 模块权限树根节点 |
| `模块:资源` | C（菜单） | `rag:project` | 菜单项，含前端路由 `path` |
| `模块:资源:动作` | F（按钮） | `rag:project:create` | 按钮级权限，可直接解析为 `(dom, obj, act)` |

### 3.5 权限注册中心（模块自治声明）

核心代码：`module_authorization/config/registry.py`。

- 各业务模块在自身 `config/permissions.py` 中定义 `ModulePermissionDefine`（含权限树 `nodes` 与新用户默认权限 `default_policies`），调用 `permission_registry.register(...)` 完成注册。
- `app.py` 导入各模块时（如 `from module_rag.config import permissions as rag_permissions`）触发注册。
- 启动时 `AuthManager.init_default_casbin()` 幂等同步到三处：
  1. **casbin 策略表**：`admin` 全局策略 + 各模块 `default_policies` 合并出的 `user` 角色策略（批量查缺补写，只增不删）；
  2. **role 表**：upsert 内置角色（不动用户可编辑字段）；
  3. **permission 表**：按 `code` upsert 权限树（M/C/F 节点，`parent_id` 关联），供前端权限管理与角色授权界面使用。

> **默认策略变更注意**：`default_policies` 只做增量同步；移除声明不会自动回收已存在的 `user` 角色策略，需在界面取消勾选或清理 `casbin_rule` 表记录。

### 3.6 数据表结构

| 表 | 来源 | 关键字段 | 说明 |
|----|------|----------|------|
| `user` | `module_authorization/do/user.py` | `id, username, password(argon2 哈希), dept_id, email, phone, nickname, avatar, is_active, created_at, updated_at` | 用户表 |
| `role` | `module_authorization/do/role.py` | `name, role_key, description, sort, is_active` | 角色字典 |
| `permission` | `module_authorization/do/permission.py` | `name, code, menu_type(M/C/F), path, icon, order_num, visible, parent_id, description` | 权限/菜单树 |
| `dept` | `module_authorization/do/dept.py` | `id, name, ancestors(祖级链,逗号分隔), parent_id...` | 部门树，支撑部门授权级联 |
| `casbin_rule` | casbin-async-sqlalchemy-adapter | `ptype(p/g), v0(sub), v1(dom/role), v2(obj), v3(act)` | Casbin 策略与角色绑定 |
| `token` | `module_authorization/do/token.py` | `user_id, token, token_type, expires_in, expires_at, is_revoked` | 刷新令牌持久化（访问令牌不落库） |

### 3.7 接口鉴权方式

#### 身份认证（`module_authorization/dependencies/auth.py`）

- `OAuth2PasswordBearer(tokenUrl="/authorization/auth/token")` 仅搬运令牌字符串，不做校验；
- `get_current_user` / `get_current_user_id`：校验 JWT 签名 + Redis 黑名单后返回当前用户；
- `get_current_user_id_optional`：可选登录，匿名请求返回 `None`，由业务自行决定策略。

#### 系统级权限校验（`module_authorization/dependencies/permission.py`）

```python
# 路由声明式校验（推荐）
@router.post("", dependencies=[Depends(require_permission("rag", "project", "create"))])

# 服务层手动校验
await enforce_permission(user_id, "rag", "doc", "upload")   # 无权限抛 403
```

- 底层 `check_permission` 调用 `enforcer.enforce(user_id, dom, obj, act)`；
- enforcer 未初始化时**拒绝所有请求**（安全优先）。

#### 新用户默认角色（`sync_default_user_roles`）

- 系统首个注册用户 → 自动绑定全局域 `admin` 角色（保证系统引导可用）；
- 其余用户 → 绑定全局域 `user` 角色。

## 4. 认证设计（JWT）

配置来源：`config.yaml` 的 `token` 段（`module_authorization/config/token.py`）。

```yaml
token:
  secret_key: '...'
  algorithm: HS256
  expire_minutes: 30000     # access_token 有效期（分钟）
  refresh_expire_days: 20   # refresh_token 有效期（天）
```

### 4.1 令牌体系

| 令牌 | 存储 | 校验 | 吊销 |
|------|------|------|------|
| access_token | 仅客户端持有 | JWT 签名 + Redis 黑名单 | 登出时写入 Redis 黑名单（TTL = access 有效期），缓存不可用时降级为仅告警不阻断 |
| refresh_token | 客户端持有 + `token` 表落库 | JWT 签名 + 数据库 `is_revoked` 检查 | 登出/管理员重置时置 `is_revoked` |

- JWT payload 中 `sub` = user_id；`token_util`（`common/utils/security/token_util.py`）统一签发/校验；
- 密码使用 `pwdlib[argon2]` 哈希（`common/utils/security/password.py`）。

### 4.2 认证 API（`module_authorization/controller/auth.py`）

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/authorization/auth/register` | 注册（返回令牌对 + 用户信息） |
| POST | `/authorization/auth/login` | 登录（同上，校验 `is_active`） |
| POST | `/authorization/auth/logout` | 登出（access 入黑名单 + refresh 置吊销） |
| POST | `/authorization/auth/refresh` | 刷新 access_token（校验 refresh 有效性 + 用户激活状态） |
| GET | `/authorization/auth/me` | 当前用户信息 |
| GET | `/authorization/auth/permissions` | 当前用户角色与权限码（前端菜单过滤/按钮权限依据，admin 返回 `["*"]`） |
| PUT | `/authorization/auth/profile` | 自助更新昵称/邮箱/电话/头像 |
| PUT | `/authorization/auth/password` | 自助修改密码（校验旧密码） |

### 4.3 用户/角色/权限管理 API

控制器位于 `module_authorization/controller/`，均受 `sys` 域对应权限码保护：

| 控制器 | 功能 | 权限码 |
|--------|------|--------|
| `user.py` | 用户 CRUD、启用/禁用、重置密码、头像 | `sys:user:*` |
| `role.py` | 角色 CRUD、角色分配权限 | `sys:role:*` |
| `dept.py` | 部门树 CRUD | `sys:dept:*` |
| `permission.py` | 权限/菜单树查询 | `sys:permission:*` |
| `casbin_rule.py` | 策略规则（p/g）查看与增删 | `sys:casbin:*` |
| `token.py` | 令牌管理 | — |

## 5. 项目级权限（以知识库 module_rag 为例）

> 代码：`module_rag/dependencies/permission.py`。**不走 Casbin 项目域**，由业务表固定档位判断（GitHub 式协作模型）。

### 5.1 档位定义（`RagRole`，存于 `project_member.role` / `project_dept.role`）

| 档位 | role | 数值 | 能力 |
|------|------|------|------|
| 只读 | `project_reader` | 1 | 只读 |
| 编辑 | `project_editor` | 2 | 读 + 写（上传/修改/对话） |
| 管理 | `project_admin` | 3 | 全部（删除/成员管理/部门授权） |

### 5.2 动作所需档位（`ACTION_LEVELS`）

| 动作 | 所需档位 |
|------|----------|
| `read` | 1 |
| `upload` / `update` / `write` | 2 |
| `delete` / `invite` / `remove` / `manage` | 3 |
| 未列出的动作 | 3（从严处理） |

### 5.3 鉴权规则

```
1. 全局管理员穿透: casbin 全局域 admin 绑定 → 直接放行
2. 生效档位 = max(直连成员档位, 部门授权档位)
   - 部门授权级联: 用户所在部门的 ancestors 祖级链 + 自身部门
     命中 project_dept 授权记录即生效
   - 达到动作所需档位即放行
3. 公开项目(is_private=false): 任何登录用户可只读
```

### 5.4 使用方式

```python
# 路由声明式（要求路径含 {project_id} 占位符）
@router.post("/{project_id}/documents",
             dependencies=[Depends(require_project_permission("doc", "upload"))])

# 服务层手动
await enforce_project_permission(user_id, project_id, "member", "remove")
```

## 7. 前端权限控制

### 7.1 权限数据来源

登录后前端调用 `GET /authorization/auth/permissions` 获取：

```json
{
  "roles": { "*": ["admin"] },
  "permissions": ["*"]            // 或具体权限码列表，如 ["rag:project:create", ...]
}
```

存入 Pinia 的 `authStore`（与 access/refresh token、用户信息一起），供菜单过滤与按钮判断。

### 7.2 路由守卫（`src/router/index.ts`）

- 路由由 `unplugin-vue-router` 按 `src/pages` 与 `src/modules/*/pages` 目录自动生成；
- `extendRoute` 按目录为路由打上 `meta.admin` / `meta.app` / `meta.standalone` / `meta.fullpage` 布局标记；
- 守卫逻辑：`meta.admin` 或 `meta.app` 的路由要求登录，未登录跳转首页并提示。

### 7.3 HTTP 层令牌处理（`src/common/api/http.ts`）

- 请求拦截器自动追加 `Authorization: Bearer <access_token>`；
- 响应 401 时自动用 refresh_token 换新 access_token 并**重试一次**；刷新失败则清除会话、强制重新登录。

### 7.4 菜单与按钮

- 管理后台菜单依据后端 `permission` 表返回的权限树 + 用户 `permissions` 权限码过滤渲染；
- 按钮级权限通过权限码（如 `rag:project:create`）判断显隐。

## 8. 新模块接入权限的步骤

1. 在模块下新建 `config/permissions.py`，声明 `ModulePermissionDefine`（权限树 + `default_policies`）；
2. 在模块被 `app.py` 导入的入口处导入该文件完成注册（如 `from module_xxx.config import permissions`）；
3. 控制器路由使用 `require_permission("模块", "资源", "动作")` 声明校验；项目内资源则实现类似 `require_project_permission` 的档位校验；
4. 重启服务，声明自动幂等同步到 casbin 策略表、role 表、permission 表；
5. 管理员在"角色管理 → 分配权限"界面为需要的角色勾选新模块的权限码。

## 9. 安全设计要点汇总

| 项 | 策略 |
|----|------|
| 密码存储 | argon2 哈希，不存明文 |
| 令牌传输 | `Authorization: Bearer`，OAuth2 标准端点（Swagger 可调试） |
| access 吊销 | Redis 黑名单即时生效；缓存故障降级为仅告警 |
| refresh 吊销 | 数据库 `is_revoked` 持久化，登出/重置即失效 |
| enforcer 异常 | 未初始化/校验异常一律拒绝（fail-closed） |
| 首用户引导 | 首个注册用户自动成为全局管理员，避免系统无人可管理 |
| 越权防护 | 系统（Casbin）+ 项目（档位）双重校验，未声明动作从严处理 |
