# 发布流程

从代码合并到生产上线的标准步骤与回滚预案。

## 1. 分支与版本约定

```
main(稳定) ← PR审查 ← dev(日常集成) ← feature/* | fix/*
```

| 项 | 约定 |
| :--- | :--- |
| 版本号 | `主.次.修订`(如 1.0.0)，与镜像 tag、`doc/tag_doc/tag_x.x.x.md` 对应 |
| 变更记录 | 每次发布新建 `tag_doc/tag_<版本>.md`，登记功能/修复/破坏性变更 |
| 待办池 | `tag_doc/tag_todo.md` 记录下一版本候选任务 |

## 2. 发布步骤

### ① 冻结与构建

```bash
# 从 dev 拉取发布分支
git checkout dev && git pull
git checkout -b release/1.0.1

# 后端: 更新 pyproject.toml 版本 → 构建镜像
cd code/backend/server_py
docker build -f tools/docker_dev/Dockerfile.dev -t server_py:1.0.1 .

# 前端: 构建产物
cd code/frontend/vue3
pnpm run build
```

### ② 部署到测试环境

```bash
# 拷贝前端产物
cp -r dist/* <部署机>/docker_compose/nginx/html/

# 切换后端版本: 修改 docker-compose.yml 的 image tag
#   image: server_py:1.0.1
cd tools/docker_compose
bash restart.sh
```

### ③ 验证清单

- [ ] 登录/退出/Token 续期
- [ ] 核心页面(文件管理/知识库)增删改查
- [ ] 权限角色(403 拦截生效)
- [ ] AI 对话流式输出
- [ ] 数据库连接与日志无 ERROR

### ④ 正式发布

```bash
# 合入 main 并打 tag
git checkout main
git merge release/1.0.1
git tag v1.0.1 && git push origin main --tags

# 生产机按测试环境同样步骤切换镜像 tag 并重启
# 记录 tag_doc/tag_1.0.1.md
```

## 3. 回滚预案

```bash
# 后端回滚: docker-compose.yml 的 image tag 改回上一版本
#   image: server_py:1.0.0
bash restart.sh

# 前端回滚: 恢复上次构建产物(建议发布前备份 html 目录)
cp -r nginx/html nginx/html_bak_<日期>   # 发布前执行
cp -r nginx/html_bak_<上一版>/* nginx/html/

# 数据库回滚: 使用最近一次备份
#   见《数据库运维》恢复章节(破坏性变更发布前必须先备份)
```

## 4. 发布纪律

1. **先备份后发布**：数据库备份 + 前端 html 目录备份
2. **一次只发一个版本**，禁止跨版本连发
3. 含**数据库结构变更**的版本，发布前必须验证旧数据兼容
4. 发布后 30 分钟内值班观察日志：`docker logs -f server_py --tail 200`
5. 涉及配置文件变更的，同步更新 `config_template_full.yaml` 与本文档
