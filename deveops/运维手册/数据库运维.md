# 数据库运维

PostgreSQL(PostGIS 镜像)的日常备份、恢复与迁移。

## 1. 部署形态

- 容器：`postgis/postgis:17-3.5`(自带 PostGIS；pgvector 可按需启用)
- 宿主机端口：`15432` → 容器 `5432`
- 数据目录：`docker_compose/postgresql/data`(务必持久化)

## 2. 备份

### 逻辑备份(推荐日常使用)

```bash
# 全库导出(压缩自定义格式)
docker exec -t <db容器名> pg_dump -U here -Fc server_example \
  > backup_$(date +%Y%m%d).dump

# 仅结构 / 仅数据
docker exec -t <db容器名> pg_dump -U here -s server_example > schema.sql   # 结构
docker exec -t <db容器名> pg_dump -U here -a server_example > data.sql     # 数据
```

### 定时备份(crontab 示例)

```bash
# 每日 2:00 备份,保留 14 天
0 2 * * * docker exec -t <db容器名> pg_dump -U here -Fc server_example | gzip > /backup/db_$(date +\%Y\%m\%d).dump.gz && find /backup -mtime +14 -delete
```

### 物理备份(冷备)

```bash
# 停库后直接打包数据目录(必须先停库,否则数据不一致)
docker compose stop postgis
tar czf pgdata_$(date +%Y%m%d).tar.gz docker_compose/postgresql/data
docker compose start postgis
```

## 3. 恢复

```bash
# 自定义格式恢复
docker exec -i <db容器名> pg_restore -U here -d server_example \
  --clean --if-exists < backup_20260101.dump

# SQL 文本恢复
docker exec -i <db容器名> psql -U here -d server_example < schema.sql
```

## 4. 迁移到新服务器

```bash
# 旧机导出(见上节备份)
# 新机:
#   ① 启动空库容器(初始化脚本可放 postgresql/init/)
#   ② 执行恢复
#   ③ 更新后端 config.yaml 的 db.host 并重启 server_py
```

## 5. 向量扩展(RAG 场景)

知识库向量检索依赖 pgvector：

```sql
-- 连接库后执行(有 DBA 权限时)
CREATE EXTENSION IF NOT EXISTS vector;

-- 验证
SELECT extname FROM pg_extension;
```

> 项目对向量库的读写已封装于后端 `common/utils/db/`，扩展安装失败会在启动日志中体现。

## 6. 日常检查清单

| 项 | 命令/方式 | 频率 |
| :--- | :--- | :--- |
| 容器存活 | `docker compose ps` | 每日 |
| 磁盘水位 | `df -h`(data 目录所在盘 >80% 告警) | 每日 |
| 备份产物 | 检查 `/backup` 最新文件时间 | 每日 |
| 慢查询 | `pg_stat_statements`(如启用) | 每周 |
| 连接数 | `SELECT count(*) FROM pg_stat_activity;` | 每周 |
